# PROVECODE

**Live demo: https://provecode.vercel.app**

**Tests passed. The 20% cap is gone.**

When the same AI agent writes the code *and* edits the tests that judge it, "all tests pass" stops meaning much. PROVECODE catches the test edits that make a broken change look green. That includes the count-preserving ones, which assertion-counting tools miss. Each edit it catches is tied to the approved requirement that the test was guarding.

```diff
  # tests/test_pricing.py: one assertion before, one after
- assert apply_discount(100, 0.50) == 80.00
+ assert apply_discount(100, 0.50) >= 0
```

An assertion counter sees no change here. PROVECODE reports:
- **S2, blocking.** An equality was replaced by a trivial bound, on the test that guards contract condition **C1: discount is capped at 20%**.
- **The reviewers' own check `chk-cap` fails** against the candidate in a no-network Docker sandbox, even though the repository's own tests pass.

The verdict is **FAILED**.

## What it does

| | |
|---|---|
| **Semantic weakening rules** | **S1** comparison weakened (`==` → `>=`, a looser `approx`). **S2** expected value made trivial (`== 80` → `>= 0`, `is not None`). **S3** exception widened, or `match=` dropped. **S4** parametrize cases removed. |
| **Standard rules** (prior art, credited) | **B1** test deleted (renames are recognised). **B2** skip, xfail or an early-exit guard added. **B3** assertion removed. |
| **Contracts** | YAML, versioned and human-approved, with a SHA-256 content hash. Tampered or unapproved contracts are rejected. A candidate that edits the contract path is blocked. |
| **Verdicts** | **FAILED > INCONCLUSIVE > VERIFIED**, decided by a pure function with no LLM. Missing evidence never becomes a pass, and static analysis alone never yields VERIFIED. |
| **Recorded runs** | Contract-owned checks and the repo's tests run in Docker: `--network none`, read-only, non-root, all capabilities dropped, with memory, CPU, process and time limits. Every report carries its SHAs, contract hash and image digest. |
| **Live in the browser** | The same engine runs in Pyodide in a Web Worker, served from the site itself. Code typed into the page is only parsed, never imported or executed, and analysis is stopped after 2 s. |

## Quickstart

Requires Python 3.11 or later and git. Docker is needed only for `record`.

```bash
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e "engine[dev]"

python demo/build_demo.py                            # deterministic demo repo in demo/.build/checkout
provecode check --repo demo/.build/checkout --base main --head candidate-weakened \
  --contract demo/contracts/checkout.v1.yaml         # FAILED, exit 1
provecode check --repo demo/.build/checkout --base main --head candidate-legit \
  --contract demo/contracts/checkout.v2.yaml --contract-base demo/contracts/checkout.v1.yaml
                                                     # INCONCLUSIVE, exit 2 (static only)
```

- **Exit codes:** `0` VERIFIED, `1` FAILED, `2` INCONCLUSIVE, `3` usage or internal error.
- **Outputs:** add `--json report.json --md report.md` to write the report files.
- **Contracts:** `provecode approve <contract.yaml> --by <name>` records an approval over the contract's current hash.

## Use it on pull requests (GitHub Action)

```yaml
# .github/workflows/provecode.yml in your repository
on: pull_request
permissions:
  contents: read
jobs:
  provecode:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: Shriram28Baskar/provecode@main   # pin to a commit SHA in production
        with:
          contract: contracts/checkout.yaml   # read from the PR's base commit, so the PR cannot edit it
```

- **Failing the PR:** a FAILED verdict fails the check. Set `fail-on-inconclusive: "true"` to fail on INCONCLUSIVE as well.
- **Where the report appears:** the Markdown report is written to the job summary.
- **Static only:** the Action runs static analysis and never executes PR code.
- **Protecting the contract:** pair it with CODEOWNERS and branch protection on `contracts/`.

## Use it in the agent loop (pre-commit, Claude Code)

`provecode guard` checks **uncommitted** test changes, from the working tree or the index. It catches a weakening before it becomes a commit or a PR. It uses the same engine and rules as `check`, and writes nothing to the repository.

```bash
provecode guard                 # working tree vs HEAD; exit 1 blocks
provecode guard --staged        # the index, i.e. what the next commit would contain
```

- **Zero configuration.** It works without a contract: any S1–S4/B1–B3 finding blocks (`--block-on weakening`, the default). If `.provecode/contract.yaml` exists, it is read from the **base commit**, so editing it in the working tree cannot relax it, and the edit itself blocks. Use `--block-on failed` to block only on contract-graded FAILED.
- **Pre-commit** (`.pre-commit-config.yaml`):

  ```yaml
  repos:
    - repo: local
      hooks:
        - id: provecode
          name: provecode guard (test weakening)
          entry: provecode guard --staged
          language: system
          pass_filenames: false
          always_run: true
  ```

- **Claude Code** (`.claude/settings.json`; `provecode` must be on the hook's `PATH`):

  ```json
  {
    "hooks": {
      "SessionStart": [{ "hooks": [{ "type": "command", "command": "provecode guard --hook claude-session-start" }] }],
      "Stop": [{ "hooks": [{ "type": "command", "command": "provecode guard --hook claude-stop", "timeout": 60 }] }]
    }
  }
  ```

  When Claude tries to finish with weakened tests, the Stop hook blocks it. Claude gets the findings, with before and after, as the reason to keep working, and you get a one-line warning. The session's starting commit is recorded outside the repository, so a weakening Claude commits during the session is still caught.
- **Not tamper-proof.** An agent with a shell can edit hook settings. The local gate is the early, cheap catch; the PR check, with the contract read outside the candidate, is the enforcement point. Hooks fail open on errors and say so (ADR 0010).

## Honest scope

- Python only: pytest-style and unittest-style tests.
- Tier A cases are injected. Real-world recall (Tier B) and precision (Tier C) aren't measured yet.
- One author wrote the patterns, the cases and the detector. The patterns and split were committed before the detector; the commit order is recorded in `tierA.json`.
- The baseline is a reimplementation of published rules, not the original tools.
- VERIFIED means no mandatory condition failed within the declared scope. It is not a proof of correctness.
- Docker is not a complete security boundary. A contract check passes only with a JUnit report of tests that actually ran, and the candidate cannot shadow the runner. Code the candidate supplies still runs in the same process as the check, though, so deliberately malicious code could forge a report.
- **Prior art:** MaruCheck already has approved, hashed contracts, contract-owned checks, deterministic decisions and inconclusive evidence. Existing count-based detectors catch deletions and skips. PROVECODE's contribution is the semantic, count-preserving rules and the benchmark (see `docs/00-competitive-audit.md`).
